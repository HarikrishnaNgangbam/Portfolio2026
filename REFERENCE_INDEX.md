# Portfolio2026 — Reference Index

## Purpose

This document records the visual references and page states that are approved or locked.

An approved reference is a **source of truth**, not merely inspiration.

If a reference is unavailable in the current implementation environment, do not invent its details. Ask for or use the exact available reference rather than guessing.

---

## Status Definitions

### LOCKED
Approved and should be preserved unless the user explicitly asks for a change.

### REFERENCE
Approved visual/structural reference to guide related work.

### EXPLORATORY
Concept under discussion; not a source of truth.

## Core Reference Relationship

The portfolio should feel like one system:

**Home → Work → Case Study → About → Contact**

Individual pages may use different content compositions, but they should share the underlying visual language.

---

## Reference Interpretation Rules

When studying a reference, evaluate:

1. Section hierarchy
2. Eyebrow treatment
3. Title treatment
4. Typography scale
5. Spacing
6. Content density
7. Evidence treatment
8. Image treatment
9. Borders/dividers
10. Colour
11. Interaction/motion
12. Responsive behaviour

Do not copy superficial component shapes while ignoring the underlying hierarchy.

---

## Critical Layout Reminder

Approved references must be interpreted together with the locked rule:

> **Hierarchy is vertical. Orientation is flexible.**

A reference containing horizontally arranged content does not imply a persistent left/right section split.

Likewise, a tall page is not automatically a vertical layout.

---

## Reference Governance

### When a reference is approved
Record it here and mark it LOCKED.

### When a reference is replaced
Do not silently overwrite the old reference. Record the new decision and identify the previous reference as superseded.

### When references conflict
Use:
1. newer explicit user decision
2. newer approved reference
3. existing locked rules

If still ambiguous, ask User + ChatGPT before implementation.
